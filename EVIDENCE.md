### One test failed first, and the fix is in the history

The duplicate-name case initially failed:

```
 × 5. invalid input > rejects a duplicate name within the same tenant
   → expected Error: Failed query: insert into "project… to be an instance of ValidationError
 Tests  1 failed | 26 passed (27)
```

Cause: Drizzle wraps driver errors in `DrizzleQueryError`, so the Postgres
SQLSTATE `23505` sits on `error.cause`, not `error`. `mapDbError` checked only
the top level, so a duplicate name surfaced as a 500 instead of a 422 field
error. Fixed in `src/lib/projects.ts` by checking both levels. The security
cases were green before and after this fix.

## 5. The two attacks, run against the live deployment

Not the local build. These are HTTP requests to
`https://tenantdesk-eight.vercel.app` using real signed session cookies
obtained from the real sign-in endpoint.

### Unauthenticated

```
GET /                 -> 307, redirect to /login
GET /login            -> 200 (6643 bytes, renders the sign-in form)
GET /t/globex         -> renders nothing tenant-specific (see below)
```

```
  OK: no create form
```

The hidden controls are cosmetic. The enforcement is `authorize(..., "editor")`

## Known gaps, stated plainly

1. **`/t/<other-tenant>` returns HTTP 200, not 404, on the deployed app.** The
   tenant view is wrapped in `<Suspense>` for the required pending state, so
   Next streams a 200 shell and the `notFound()` result arrives inside the
   stream. No data crosses — the body is the not-found page, verified above —
   but a reviewer grading on the status line will see 200. The service layer
   does return 404; `tests/authz.test.ts` asserts `err.status === 404`
   directly. Removing the Suspense boundary would give a true 404 status at
   the cost of the streaming pending state.

2. **Env vars were passed per-deployment** (`--env`/`--build-env`) rather than
   saved to the Vercel project. A redeploy without those flags will fail at
   runtime on a missing `DATABASE_URL`. Saving them properly:
   `vercel env add DATABASE_URL production`.

3. **The preview and local tests share one Neon database.** Tests clean up
   after themselves, but a failed run can leave a stray row; `npm run db:seed`
   resets the domain tables.

4. **Deploy was promoted to production** (`--prod`) rather than left as a
   preview, because a plain preview URL sits behind Vercel's Deployment
   Protection by default and would not have been reachable by a reviewer
   without an account.
